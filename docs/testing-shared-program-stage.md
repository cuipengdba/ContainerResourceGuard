# 共享程序切换与独立恢复实测

[接口修正冻结计划](test-plan-shared-program-stage-interface.json)之后，在全新独立原镜像克隆中完成两角色共享程序文件的切换和独立恢复。产品仍为每个容器一个Agent；这是一套临时宿主侧验收夹具。完整数字与源摘要见[机器记录](test-results-shared-program-stage.json)。

真实Linux正式基线拒绝检查先通过：默认只读、显式执行均返回not-ready，原程序/journal/进程/cgroup/目录条目不变，未创建锁、输出或恢复目录，未调用切换CLI。首次克隆启动另因误打包较新campaign/engine脚本被摘要保护拒绝，尚未创建克隆或负载；旧上传、日志和句柄保留，换成原冻结脚本后再运行，未变更预算、源码门或验收标准。

首轮候选采样55次不足59次、第二轮旧工具不支持managed-smoke的失败分别保留，均已恢复及清理；未覆盖或计作业务通过。本轮固定短时工具及CLI能力，两个600秒阶段使用同一套工具；正式86400秒保留原工具，负载worker、数字预算/期限和验收标准不变。

两个角色均完成原observe600秒和新enforce600秒，沿用同一64MiB数据、原SQL/API门槛和引擎备份/同步/独立恢复周期。共享替换前先停用两容器并核对原值，创建持久不可变备份，再写两份配置、原子换共享程序，由各自原helper启动单一候选Agent。候选保持120秒以上，原业务/cache/PG、profile字节与mtime、五项非目标控制和OOM条件均保持。

新负载结束且原工具完成临时清理后，用独立进程调用--recover；核对同次私有记录、源与备份，旧参考入口恢复实际原值，再还原旧配置/程序、由同一helper启动旧observe Agent，不导入或删除journal。两个Pod、各自cgroup及namespace正常清理，独立确认namespace缺失，原24h基线未修改。

终态另以只读检查确认两阶段PG启动时间相同、前阶段最终五项校验和等于后阶段初始值、64MiB载荷保持，旧源/备份/profile及每日日志0600保留、协调入口结束、两cgroup与namespace独立缺失。此后再尝试正式execute，已通过的共享演练门确实通过，但原24h基线尚未完整接受，因此仍not-ready；锁/输出/原基线源、journal、进程和控制不变。

两条源提交的完整CI、原生ARM64 CI均通过，ARM上也运行了13项验收门检查。这些CI是工具/单测/构建证据，不能追加为ARM厂商业务或本次控制器实测。

本轮只验证手动7.2核/20001980416B/读写各64MiB/s和4096IOPS下的切换与恢复。正式24h enforce仍须等待原完整86400秒基线和四周期终态，再重验所有实时身份/条件并归档；至少7天、默认20%业务失败及其他既有门槛不变。已发布工程预览的二进制和标签未改。
