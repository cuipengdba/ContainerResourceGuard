# 分区IO修复设计与验收（P04/P06，开发中）

首轮真实分区失败保留在[原报告](testing-native-cgroup-partition-first.md)。本分支基于08f254d组合线开发，不改变正式长测的固定程序、预算或已发布资产。未通过真实分区验收前不发布、不宣称分区支持完成。

Linux6.8的[blkg_conf_open_bdev](https://github.com/torvalds/linux/blob/v6.8/block/blk-cgroup.c)拒绝分区设备号；[sysfs规则](https://docs.kernel.org/7.0/admin-guide/sysfs-rules.html)要求解析真实设备树并核对设备属性。路径不按sda1/nvme等名字裁剪，不拿父盘身份充当分区身份。

实现合同：

- 文件系统设备、缓存身份、io.max控制设备、控制设备身份分别解析。整盘沿用已有身份摘要；分区身份使用带版本的独立摘要，包含父盘稳定身份、分区号、起始扇区及长度。缺父盘稳定UUID/WWID、几何越界、错误/不可读设备树或中途变化均拒绝。
- 只沿实际sysfs block父级找所属整盘，并交叉核对/sys/dev/block索引、dev、subsystem和几何；不将LVM/DM无条件展开成物理底盘。每次应用/恢复仍核对自身cgroup和目标整盘身份，写入只在本容器叶子cgroup。
- manual同盘多个路径只生成一份整盘限额；percent同盘多个分区profile按四维分别取最小基准后乘io_percent，形成该容器对整盘所有分区IO共享的上限，不叠加预算。同组混入整盘profile则跳过；不同控制设备如有上下层重叠继续跳过。
- journal仍只记录实际修改的整盘设备及其原稳定身份/原值。整盘身份算法、journal字段/版本不变，分区消失不应阻止恢复尚属同一盘的本容器原值；替盘仍拒绝恢复。旧程序不认识新分区摘要时应报告未覆盖，不伪装旧程序可限制分区。
- 自动最大文件系统选择、标定前后设备核对、稳定profile复用及路径覆盖都使用同一解析合同；分区几何或父盘身份变化使缓存失配。标定不解除原有/祖先限额，失败不等待或阻断业务。
- 维持只有CPU/内存/IO三独立百分比，各默认20；无新资源参数，无宿主/其他容器控制入口。

验收分开记录：设备树/错误输入/重新编号/旧整盘摘要和journal的单元/race检查；整盘既有22项回归；新建独占设备上的真实两个分区共享限额、直接IO、自动标定/缓存失配、外部原值及恢复/新ID检查。只读系统盘清单可核对解析，不能替代真实分区IO效果；禁止格式化或写已有系统盘。物理独立多设备、ARM厂商业务、24h+24h及7天条件不变。
