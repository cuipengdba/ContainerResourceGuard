# 本地指标隔离实测（未发布）

2026-11-10，源码 5c707d9，SHA256 `ddc3c23a0215b53a82bfb4b1bdf1e36ac4dcfe66b6eab5397c05d8c567483279`。Linux 5.14、amd64、cgroup v2，在独立占位业务容器内完成 10 项检查，见 [JSON](test-results-metrics-linux-amd64.json)。不是厂商业务负载的指标开销验收。

默认关闭时不生成文件；开启后输出 2422B、0600 的本地指标，不含容器 ID/业务路径；持续开启 3s 的 1Hz 协调期间未重复改写。向指标路径放置测试符号链接后，导出失败且目标标记内容不变，CPU 仍能从 0.25 调整至 0.3 核，业务 PID1 继续运行。移除本次测试链接并重新启用指标后恢复导出。disable 恢复 CPU/内存真实原值，保留最后指标文件供按时间戳判断过期。

每次显式启用触发首份采样，持续开启期间最多每分钟一次；本次故障测试使用关闭/开启触发新尝试。没有将重复切换描述成全局一分钟内只能有一次写入。

初次命名空间删除等待超时，随后独立确认命名空间不存在；未强制移除 finalizer、修改其他命名空间或删旧 journal。此清理异常保留在 JSON，没有把第一次等待改成成功。

对应源码 Go 1.22.5 的 Linux vet/race、16 个建模 SIGKILL 检查点、12 个辅助启动故障检查及 [CI](https://github.com/cuipengdba/ContainerResourceGuard/actions/runs/42693288738) 通过，guard 语句覆盖率 71.5%。抽取共享文件写入函数后，journal 仍使用同步文件/目录落盘，指标走可丢弃的非 fsync 分支。

尚未完成长时低 IO、持续满目录、业务高峰与 CPU/RSS/写入量预算；不把这 3 秒限频观察当成 30 分钟或长期性能结果。
