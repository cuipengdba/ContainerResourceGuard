# 安装包文档与完整验收证据

开发中的打包修复已完成[完整Linux CI](test-results-quality-package-CI.json)，两分支的原安装包、完整性及可重复检查均通过，未修改验证器。当前已发布preview.4附件保持原样。对应P10.2/P10.3，安装包仍使用已构建的准确ELF、BUILD、SBOM、确定性tar/gzip及外部SHA绑定；离线验证器不放宽。

首次CI发现历史验收文档指向未打包的冻结测试源码；进一步检查还发现docs已有132034033字节，多个JSON超过单成员2MiB和总128MiB的原解包边界。不能通过移除检查、扩大安全边界或把整个源码工作目录塞进包解决。

新的收集器只读取指定提交的git archive：跟随Markdown引用补齐已提交的源码及其文档；未引用测试数据和任何未跟踪文件不进入包。缺失目标、链接/特殊文件、目录穿越、字节码和超大必需脚本拒绝。目录引用包含已提交子树。

超过2MiB的历史docs JSON/JSON.gz留在GitHub，安装包内对应Markdown链接改为该package_revision的不可变链接，其他小文件不改字节。生成PACKAGE-DOCUMENTATION.json记录遗漏原件大小/SHA/固定URL、链接转换及修改前后Markdown摘要。部署包因此有完整可解析的文档入口，但完整历史证据重放须使用匹配提交的仓库；不会把远程数据说成已离线捆绑。

公开文档最多4000成员、60MiB，为原4096成员/128MiB、64MiB ELF及其他元数据留余量；非ELF单成员仍不超过2MiB。固定源归档、排序、时间及gzip参数保持。验证器scripts/verify-release.py、check-package与完整性/可重复构建检查均不改。

[本地13项检查和首轮CI失败](test-results-package-document-closure-local.json)覆盖传递链接、碎片、目录、未引用数据、超大证据固定链接与原件摘要、确定性、缺目标/越界/反斜杠/符号链接/超大脚本/字节码拒绝及实际提交闭包。新增检查已纳入CI。修复前准确源提交的本地闭包为819成员、39460473字节，最终包须继续通过原两架构检查和完整性验证。
