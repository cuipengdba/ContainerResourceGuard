# 自动标定辅助故障：真机路径实测

2026-11-10，在全新隔离夹具保留原镜像、数据库参数、真实容器路径和`/opt/ccg`只读挂载，RC3候选验证DBS、1.0组合候选验证HISDBS。两类业务各10个场景，共20个场景、108项检查全部通过；每个自有Pod及最终namespace均已删除。源提交及二进制摘要见[结果JSON](test-results-realpaths-faults.json)。

| 场景 | 观察与判定 |
|---|---|
| CRG缺失、配置错误、崩溃、挂起、忽略TERM | 原业务PG及API在90秒内就绪；原缓存45秒观察窗内enforce；SQL及原ls探针正常；业务TERM在12秒内完成 |
| 回退为原supervisor | 核对原脚本摘要，保留原业务和缓存启动/终止链 |
| cgroup只读 | 各项控制被跳过、原内核额度不变，业务正常；本场景仍发生首次标定，不能宣称在测速前发现cgroup只读 |
| 标定结果目录只读 | 输出权限检查跳过测速，原业务/缓存继续；CPU/内存可独立生效并诚实报告降级 |
| 状态目录只读 | 在测速及首项控制写入之前拒绝资源接管，不影响原业务 |
| 标定期间取消 | 核对当前容器Agent摘要与打开的专用临时文件，向实际标定Agent发TERM；取消后未保存新profile、未写首项额度，业务/缓存仍正常 |

所有场景还检查PID1身份、OOM计数、SQL/原探针及原业务TERM。这里只证明对应故障下辅助进程不阻断业务；不把90秒启动/12秒停止替代原生600秒或长时性能标准。此次覆盖为RC3/DBS和组合候选/HISDBS，不外推另外两个候选/角色组合。

无权限能够放行业务，并不表示已经成功控制资源。生效的严格IO/内存等额度仍可能使业务变慢；自动30%业务负载失败及手动16MiB/s的SQL错误继续保留于[真实路径记录](testing-realpaths-progress.md)和[手动对照记录](testing-realpaths-manual.md)。

另已冻结[交叉候选/角色故障补齐计划](test-plan-realpaths-faults-reciprocal.json)：组合候选/DBS和RC3/HISDBS，仍为每组10场景。该条件任务等待在线维护任务终止并独立确认自有namespace不存在后才创建夹具，不提前标为通过。
