# 跨周期内存稳定窗口（开发功能）

此功能位于 next/local-diagnostics，承接 P05.2/P05.4，不属于已发布 RC2。最小配置仍为 `{"percent":20}`；新增的可选运维参数 memory_stable_seconds 默认 0，保留现有瞬时安全预检。

```json
{"percent":20,"memory_stable_seconds":30}
```

非零值允许 2–3600 秒。下调 memory.max 或 memory.high 时，要求经过指定时间且至少三次相隔一秒以上的安全观测；按 Agent 原有 interval_seconds 协调，因此实际等待可能长于配置窗口。CPU、IO 和放宽内存不等待这个窗口。它不调整限额数值，不强制回收，也不修改数据库或原缓存程序。

每次仍执行原来的 50ms 双采样、5% + 16MiB 余量和增长预留；另比较跨周期增长及 high/max/oom/oom_kill 计数。观测中断、时间倒退、目标/当前值/窗口变更、进入 observe、事件变化、危险增长或无效统计均重新等待。需要完整四项 events；内核没有 PSI 接口时仍可工作，但不能据此断言无内存压力；若提供 PSI，则严格解析并检查现有压力阈值。

历史只存当前 Agent 内存，重启后重新积累。没有完成窗口时不反复落盘写意图；窗口完成后照常持久化真实原值及写意图，并再次检查用量和所有权。采样存在竞争窗口，不能保证未来分配绝不 OOM。

逐项结果仍使用 state=skipped 表示尚未施加，新增 reason_code=memory_window 表示等待，memory_safety 表示用量、事件、压力或统计不符合安全条件。解释不包含每秒变化的倒计时，以免等候期间产生重复状态写入。

run --once 不会等待足够的跨周期观测，需使用常驻 run。显式 restore/disable 携带包含此参数的 --config 时，在命令内每秒重试，最多等待窗口长度加约 3 秒；再次遇到其他安全失败则返回未完成。命令不会强行降低内存或接管业务。未指定配置时沿用原有瞬时恢复保护，不从旧 status 推测安全策略。停用标记与恢复成功分别判断，不能把恢复未完成写成全部完成。

本次 Windows 单元/vet 已通过，覆盖观测间隔、目标/模式变化、统计错误、跨周期增长、慢持久化期间分配、低原值恢复及等待期间不写日志。b0ed1e0 的 Linux 竞态/强杀及 11 项真实 cgroup 检查通过，见 [实测](testing-memory-window.md)；原缓存高峰与长时共存继续待验收。
