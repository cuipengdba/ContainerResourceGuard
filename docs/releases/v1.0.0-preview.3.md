# ContainerResourceGuard v1.0.0-preview.3

2026-11-12按用户即时更新环境的要求发布。可直接下载的工程预发布版；程序与preview.1、preview.2逐字节相同，本版汇总最新升级、回退和Agent生命周期实测文档。稳定1.0及长期验收尚未完成。

## 功能与配置

- 每个容器独立运行一份Agent，仅默认限制CPU、内存、IO。三个独立百分比省略时各自默认20%。
- 设置和标定前检测cgroup：v1跳过并记录日志；混合或未知版本跳过；纯v2通过自身目标、权限、外部限额和内存安全检查后设置。
- Pod或容器重建后重新发现自身cgroup，不固定容器ID，无需Operator或重装Kubernetes。
- 默认后台选择最大合格可写本地块设备文件系统进行IO标定并按稳定设备身份复用profile，无需手工指定目录。IO百分比是实测基准的比例。
- 每天一个日志文件，保留30个日历日，或总量超过1,000,000,000字节时清理最旧文件；文件日志失败降级stderr。
- 通过可选helper独立启动；权限不足、只读、标定或Agent失败不阻断原DBS/HISDBS启动链。已生效的资源硬限额仍会影响业务，不能用Agent退出代替停用恢复。
- 保留已有热重载、诊断、停用恢复、冲突保护、维护升级/回退及分区设备解析；不新增其他资源的默认控制。

```json
{"cpu_percent":30,"memory_percent":40,"io_percent":25}
```

以上仅为语法示例。更新已有环境时保留当前配置、IO profile和state_dir，不用空配置覆盖现有配额。默认20%尚未通过原DBS/HISDBS四格业务验收；内存硬上限过低可能导致OOM。

## 下载和更新

[GitHub下载页](https://github.com/cuipengdba/ContainerResourceGuard/releases/tag/v1.0.0-preview.3)提供两架构压缩包、SHA256SUMS、构建清单及证据。在新建的私有空目录内下载实际架构的包并核对摘要：

```bash
curl -fLO https://github.com/cuipengdba/ContainerResourceGuard/releases/download/v1.0.0-preview.3/containerresourceguard-v1.0.0-linux-amd64.tar.gz
curl -fLO https://github.com/cuipengdba/ContainerResourceGuard/releases/download/v1.0.0-preview.3/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf containerresourceguard-v1.0.0-linux-amd64.tar.gz
./crg version
./crg build-info
```

每个容器分别更新。先私有备份原程序、配置、profile、journal和状态；只停止对应CRG辅助循环及Agent，确认旧写入者全部退出，再通过同目录临时文件加原子替换安装，恢复原helper。保持原state_dir，不能删除journal绕过校验。旧rc.3-preview.1缺少新维护协议广告，不能假定binary-install直接跨过保护，具体见上述已发布版本升级实测和[安装文档](../installation.md)。

已运行preview.1或preview.2的环境，程序相同，无需重启Agent来获得新功能。接入路径见[容器集成](../integration.md)。启动后核对状态及日志：

```bash
/opt/crg/crg status --config /etc/crg/config.json --format human
```

检查`/var/log/crg/crg-YYYY-MM-DD.log`的cgroup版本、skip/degraded原因和实际限额。此次只发布GitHub下载包，不替换现有环境、不重启数据库。
