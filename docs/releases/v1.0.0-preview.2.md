# ContainerResourceGuard v1.0.0-preview.2

2026-11-11按用户“马上发布、用于更新环境”的要求交付工程预发布包。程序与preview.1完全相同，本版更新文档及验证证据；稳定1.0和长期验收继续。

## 功能和配置

- 每容器独立运行一份Agent，只默认限制CPU、内存、IO，三个独立百分比省略时各自默认20%。
- 先判断cgroup版本：v1跳过并打印原因；混合/未知跳过；纯v2通过自身目标、权限、外部限额和内存安全检查后设置。
- Pod或容器重建后重新发现自身cgroup，不固定容器ID；默认后台选择最大合格可写本地块设备文件系统做IO标定，按稳定设备身份复用profile。IO百分比是实测标定基准的比例。
- 每天一个日志文件；保留30个日历日，或总量超过1,000,000,000字节时清理最旧文件。文件日志故障降级到stderr。
- 无权限、只读cgroup、标定失败或Agent故障均不能成为DBS/HISDBS启动的前置条件；沿用原业务启动链，辅助进程独立启动。
- 保留现有热重载、诊断、维护升级/回退、停用恢复、外部修改冲突保护、分区设备解析及历史手动配置兼容。其他资源不新增默认限制。

```json
{"cpu_percent":30,"memory_percent":40,"io_percent":25}
```

这是语法示例。默认20%在原DBS/HISDBS四格业务验收中均未通过，更新环境时保留现有已核对的配额与状态，不直接用空配置覆盖。容器总体内存硬限额过低仍可能导致业务OOM；Agent失败不阻断业务不等于资源限额不会影响业务。

## 下载、校验和更新

[GitHub下载页](https://github.com/cuipengdba/ContainerResourceGuard/releases/tag/v1.0.0-preview.2)提供amd64/arm64包、SHA256SUMS、构建清单及证据。选择实际架构，将包和SHA256SUMS放在新建的私有空目录中：

```bash
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf containerresourceguard-v1.0.0-linux-amd64.tar.gz
./crg version
./crg build-info
```

每个容器分别更新。先备份程序与配置，保留原config、IO profile、journal、state和日志；只停止旧CRG辅助循环及Agent，核对全部旧Agent已退出，再用同目录临时文件加原子替换安装新程序，并通过原可选helper启动。保持原state_dir，不删除journal绕过校验；旧八资源开发配置须先用匹配旧版本disable并确认额外限额已恢复。旧rc.3-preview.1未广告新维护协议，不能假定binary-install直接跨过其保护。

无需重装K8s或部署Operator；业务主进程维持原启动方式。接入持久化与准确路径见[安装升级](../installation.md)和[容器接入](../integration.md)。首次接入先用doctor只读检查；沿用配置运行后核对状态与日志：

```bash
/opt/crg/crg doctor
/opt/crg/crg status --config /etc/crg/config.json --format human
```

检查`/var/log/crg/crg-YYYY-MM-DD.log`中的cgroup版本、skip/degraded原因及实际控制值。需要恢复用匹配版本disable并核对原值；杀Agent不会撤销内核已写入的限额。

已经运行preview.1的环境无需替换程序来获得新功能，两版ELF逐字节相同。本次只发布GitHub包，没有替换任何业务环境。
