# ContainerResourceGuard v1.0.1

本次补丁加入按容器配置的 `memory.high` 自动恢复。沿用 `interval_seconds`，设为 `60` 时每分钟检查一次。旧配置保持原冲突处理。

```json
{
  "interval_seconds": 60,
  "memory_high_recovery": true,
  "memory_high_recovery_paused": false
}
```

将以上字段合并到现有配置。恢复目标取自当前已验证策略。CRG 只恢复同一 cgroup 中已经成功应用、回读的有限目标漂移到 `max` 的情况。写入前再次确认身份、配置和实际值，写入后回读。维护期间可热重载暂停。未决写入、外部较严限制、写入失败和重复覆盖保留冲突并告警。一次尝试后 10 分钟内再次覆盖同一目标会暂停该 journal 条目的自动写入。

隔离 Linux 测试验证了 DBS 示例 30 GiB、HISDBS 示例 15 GiB、检查周期、热重载、维护暂停、换容器和重复覆盖。96 MiB 软阈值压力下，`high` 事件增加，短 SQL 查询零失败，吞吐下降。测试在临时 PostgreSQL 容器完成。171 的部署与业务验收仍待单独执行。[配置和维护](../memory-high-recovery.zh.md) · [内核回读和事件日志](../test-results-memory-high-recovery.json) · [Linux 验收](https://github.com/cuipengdba/ContainerResourceGuard/actions/runs/44692261670)

安装包提供 Linux AMD64、ARM64，以及 SHA256、SBOM 和构建信息。升级时保留各容器独立配置、状态和日志。旧版本可能拒绝读取新增的配置键和 journal 字段，回退前请核对目标版本的兼容性。详见 [GitHub Release](https://github.com/cuipengdba/ContainerResourceGuard/releases/tag/v1.0.1) 和 [安装与回退](../installation.md)。
