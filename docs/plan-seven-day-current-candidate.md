# 当前候选七天综合验收安排

本安排承接P10.2/P10.5与R24，仅准备隔离测试，不表示七天已开始或1.0已完成。[冻结的程序、工具、门槛与后置工作](test-plan-seven-day-current-candidate.json)是执行依据。当前组合固定d3706f3，AMD64摘要3a1ce7dbf5630f8f1c823005ceb4958653c6c235b2ba5026956ca6597f1926f9；所有结果继续限定源码、实际程序和预算。

1. 当前程序的业务、故障、升级/回退和冷重建分别通过并清理；先等真实维护及冷重建终态、退出0和独立namespace缺失，再创建七天Pod。每次创建前宿主可用内存至少28GiB，期间至少8GiB，数据盘至少20GiB。
2. 原镜像、start.sh、PG参数、容器路径及只读原缓存挂载保持，DBS/HISDBS各一份Agent/配置/状态/日志。独立空测试目录和回环DCS，其他网络关闭。手动预算仍为CPU7.2核、内存20001980416B、读写各64MiB/s和各4096IOPS，其他5项保持原值。
3. 两角色均原生实际604800秒，SQL每2秒、`/test`每5秒，零错误、最大5秒、p95桶上界1秒、98%覆盖、64MiB完整性、同一PG/PID1/Agent/缓存、无新增OOM和固定8项实际控制。每60秒宿主采样，覆盖至少98%、相邻不超过120秒。首次第300秒及每6小时一次，共28周期，每角色每周期10项备份/流复制/独立恢复内容检查；必须被完整原生区间覆盖后才从native-pending转通过。
4. 连续阶段保持主库身份，故障/重建不塞进该段而制造中断通过。结束后清理自有精确UID命名空间，保留七天使用后的数据/配置/日志/原值状态；后置必须验证这些实际老化状态的备份、恢复、新Pod身份、旧journal隔离、日志追加和升级回退，并补辅助故障检查。连续七天本身只关闭连续组件，报告固定P10_complete=false，后置代码和执行结果另行归档。
5. 原fc2的24h observe与固定d6的等时enforce独立继续，七天在宿主预留允许时并行，不改其程序、配置或控制。完整七天综合结果、原24h+24h、最近两个已发布次版本维护及52项/支持边界审计全部达标，才判断1.0；当前没有硬件的项目不据此免除。

该轮是现有Linux5.14/AMD64/单设备、私有64MiB合成负载和既定业务接口的手动预算验收，不改写默认20%失败，不证明自动30%或ARM厂商/独立物理多盘，也不冒充未知厂商专用接口或生产SLA。新的源程序若需要更换，须重新明确证据范围，不把旧二进制七天结果换名。

执行器只在测试节点管理其自有夹具，产品仍一容器一Agent，不引入宿主产品守护进程或Kubernetes控制器。宿主采集器只读核对，主动停止只定位本轮负载；外层夹具清理也核对精确namespace UID。新增TERM包装只把停止请求转为原采集器可捕获异常，让原有负载/临时实例清理执行，不修改冻结工具的业务门槛或源码。
