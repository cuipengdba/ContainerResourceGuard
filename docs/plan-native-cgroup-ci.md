# 原生容器控制器CI：运行前冻结计划

P06.1/P06.2/P06.4承接[原生基础CI](native-arm64-ci.md)之后的实际内核控制验证。[驱动与工作流摘要及数值条件](test-plan-native-cgroup-ci.json)已在首次push前冻结；[工作流](https://github.com/cuipengdba/ContainerResourceGuard/blob/main/.github/workflows/native-cgroup.yml)及一次性驱动已实现，尚无执行结果。已有ARM64单测/脚本成功不能关闭本项。

## 环境与隔离

计划使用GitHub公开仓库的`ubuntu-24.04`与`ubuntu-24.04-arm`临时VM，分别断言实际机器/Go宿主架构，记录内核、Docker与cgroup版本；不按runner名称推断6.x。若实际不是纯v2或缺少所需控制器，保留未通过/不可执行原因，不当作通过。

只在这些临时VM运行。由静态Go占位PID1、原生CRG及既有有界load程序从scratch本地构建夹具，不下载厂商镜像，不接入业务节点或原24h基线。容器独立PID/挂载/网络命名空间、network none；不挂载Docker socket、宿主业务目录或GitHub凭据。仅本轮随机标签/ID的临时容器、镜像和目录可清理。

测试驱动只是一次性CI夹具，不是产品守护进程；每个容器仍仅一个CRG。所有实际值采集绑定Docker ID、PID/start_ticks、叶cgroup和已构建程序摘要，不接受用户传入cgroup目标。重建前确认旧容器及叶组消失。清理走正常TERM/stop/remove，验证标签与身份，不无条件清空Docker或递归删除宿主目录。

## 实际三项控制与恢复

先采用固定手动CPU0.5核、memory.max128MiB、读写各4MiB/s及256IOPS。原始CPU/内存限制需高于候选，八项原值在Agent启动前记录；原生Agent仅修改cpu.max/memory.max/io.max，其他五项全程不变。

1. 实际启动唯一Agent，核对计划/状态与真实内核回读、v2日志、每日0600文件及占位PID1身份。
2. CPU负载8秒：记录cpu.stat与实际墙钟，必须有节流增量，平均消耗在0.2至0.65单核之间；不以文件回读替代节流证据。
3. 手动预算下顺序读/写及随机写各6秒，使用已有O_DIRECT有界load程序；初始化也受限，单次命令固定45秒上限。带宽和随机IOPS均须大于0且不超过配置的1.35倍，保留实际设备/计数。不能抬高预算或延长原命令期限换通过。
4. 内存先核对真实限额并运行32MiB/4秒安全分配，OOM kill保持0。这一步不宣称已经完成ARM64的内存耗尽边界验收；后续如增加有界OOM用例，必须另有明确受害工作进程与保护/清理设计。
5. 经PID身份和源摘要确认后只强杀本Agent子进程，检查限额仍由内核保持、PID1不变；同一程序/状态重新启动，核对唯一Agent和原值journal。明确disable后必须恢复真实八项原值且Agent退出，PID1继续存在。

## 独立百分比、重建及权限降级

另用新私有状态验证cpu_percent10/memory_percent1/io_percent20和默认自动选盘/标定，不提供目录/profile覆盖。宿主容量由VM实际在线CPU和/proc/meminfo独立采集，Docker初始预算需允许请求值；按真实profile分别计算CPU/内存/四项IO期望，不能用手动预算或伪造profile冒充自动标定。首次就绪保留产品原180秒标定预算，加固定30秒观察窗口，合计210秒；普通启动及重建就绪30秒。失败保留，不延长命令或标定期限。

同一配置/数据/状态/日志/profile下正常移除再创建新容器，检查新ID和身份日志隔离、旧journal归档、稳定设备profile内容/mtime复用、每日日志追加以及新的原值恢复。不运行第二次测速来掩盖复用失败。百分比阶段不以另设IO最低值改变用户预算，也不据此宣称DBS/HISDBS性能。

权限场景采用真实只读cgroup挂载并撤销容器能力，独立可写状态/日志。要求占位PID1存活、实际八项控制不变、v2判断及只读/权限原因可见；辅助退出或降级均需如实记录，不能把无设置权限报告成managed。停用和清理仍须核对无写入者。

## 结果边界

每个架构记录精确源码/程序摘要、环境、完整通过与失败、实际资源/进程/IO数据、正常清理结果，下载后长期归档；首次失败不能由后续复测覆盖。两种架构独立判定，不因另一格通过而合并全绿。

即使全部通过，也只覆盖本次原生临时VM/Docker/占位PID1；不能替代ARM64 DBS/HISDBS原镜像业务、独立多设备/映射栈、真实掉电、24h+24h、至少7天和两个已发布次版本的完整升级。实际内核若不是6.x，Linux6.x门槛继续开放。
