## 本轮结果

910五个自有进程场景的18项检查通过，原Go测试及新增准入回归共14个顶层测试通过。此前906首次真实加载被内核拒绝，仍完整保留为失败。没有DB、SQL、HTTP、Pod或生产目标参与本轮；不能据此宣布厂商诊断、完整600秒联调或稳定1.0已经通过。

“检查通过”包括负例按预期保留不完整，绝不等同于全部原始流完整。启动前已在途调用的4096返回仍在原始事件中，原始incomplete仍为true。关闭后新线程的32次普通write进入和128条原五函数边界事件保留，未创建新八阶段gate。超时场景仍保留活动syscall状态，原始与已准入视图同时标记不完整；观测到从closing通知到终态约1.969秒，包含一秒排空期限及随后perf读取、报告序列化和主机调度，不声称整个退出耗时只有一秒。

## 机制及适用边界

全部40个探针安装并再次核对目标身份后才启用目标map。首次观测到该线程的受监控syscall进入，才建立准入状态；map键同时包含pid_tgid与经BTF验证的task_struct.start_boottime，当前上限1024条状态、函数深度64。实机验证主线程启动时间换算与/proc start ticks相符；实际TID复用及map满、深度溢出故障尚未验证，不能只靠结构设计宣布已覆盖。

原始事件全部保留，另以标记区分已准入、边界和无效事件，再生成附加的已准入视图。原严格LIFO配对文件与scope helper逐字节保持，原始incomplete不会被附加视图覆盖。原五函数继续保留边界事件。scope调用入口明确新增规则：关闭后不为新普通write建立八阶段gate；已有被准入调用的gate继续到其返回。不能表述为整个调用入口过滤与旧版完全不变。

新增两个map，共7个；另有一个仅用Program.Test执行、从未挂接的关闭控制程序，共40个挂接程序和1个控制程序。关闭阶段以原子加提交；各探针在读取阶段前增加在途guard，完成状态和原始输出后才减guard。停止时先关闭新调用准入，在一秒内继续读取并等待已准入状态与guard排空；超时就显式失败，随后按原150ms perf排空结束，不补造返回记录。关闭通知测试接口只允许直接自有15秒计划、无ReaderDelay且无vendor fixture；vendor输入实测在创建BPF对象前被拒绝。

五组均为40个挂接程序、1个未挂接控制程序、7个map；perf丢失、BPF输出失败、scope错误/剩余、准入错误均为0，前后实际perf映射均3244032字节，原16MiB预算、20000事件、32MiB报告上界及业务超时没有放宽。所有边界计数与原始记录精确一致。五个探针均自然退出并删除其私有写入文件。

## 首轮失败及清理

906计划18项，实际只记录Go测试1项通过，其余17项未执行；第一个sys_enter_write加载被内核以unreachable insn 360拒绝，目标map尚未启用。生成器对无需使用的hook仍生成no-active退出分支，形成不可达指令。908修正为仅对syscall/function退出hook生成该分支，运行条件与夹具检查不变；910仅admission.go及重编译的两个ELF摘要改变。原失败源码和报告保留，未重写为通过。首轮终止了自有测试探针，标记forced_own_cleanup，不宣称其数据文件自然清理。

两轮完整BPF清单和PID/start独立核对确认14个注册进程身份与248个自有程序/map对象已消失；launch/worker同身份只计一次。清理结论只针对报告注册的进程与实际对象，不泛称系统所有进程或文件均已清理。长期任务未被挂接或重启。
