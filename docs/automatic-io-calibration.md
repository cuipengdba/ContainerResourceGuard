# 自动 IO 标定与真实路径验收（R25 / R26）

2026-11-10 用户要求按 DBS、HISDBS 真机路径测试，并将原 `crg calibrate --directory /data --output /etc/crg/io-profile.json` 的手工步骤改成默认自动完成。本轮“两个版本”暂按当前 RC3 开发线和 1.0 组合开发线执行；两种业务都纳入验收。对应 P01.7、P04.1、P10.5。已发布 RC2 的行为保持为历史事实，未发布候选不冒充正式版本。

## 默认使用

仍然只填 `{"percent":20}`。由原 supervisor 异步启动可选 CRG，业务及缓存程序独立启动。percent/enforce 模式的 Agent 在取得自身两个写入锁后、首次应用资源计划前，自动检查 IO 基准；不需要执行标定命令、填写目录或输出文件。默认输出 `/etc/crg/io-profile.json`，安装时须提供容器独立的可写持久位置。缺权限、只读输出、空间不足或测速失败会报告降级，业务不等待、不因 CRG 失败退出。标定本身会产生真实磁盘负载，不能承诺对共享设备完全没有性能影响。

`observe`、`manual`、doctor/preflight/status 和协调循环不主动测速。高级选项 `"io_calibration":"off"` 可关闭首次自动标定；默认 `auto`。手动资源模式继续使用明确绝对速率，不需要性能基准。热重载不会触发测速；auto/off 的启动标定行为在下一次 Agent 启动生效。

## 自动选盘

只读取自身 `/proc/self/mountinfo`，不扫描宿主目录树或其他容器，不调用 Kubernetes API。选择可写、可进入、至少有 384MiB 可用空间、可获取稳定块设备身份的本地磁盘文件系统，按 `statfs` 总容量降序；同容量按容器内挂载路径字典序确定一个目录。容量指整个文件系统，不是目录现有文件大小或剩余空间，也不保证等于底层整盘容量。一个文件系统有多个 bind mount 时只在选中的一个目录测速一次。

排除只读挂载、单文件挂载、隐藏/变化的设备、overlay、tmpfs、proc/sys/cgroup 及 NFS 等网络文件系统。首批候选类型 ext2/3/4、XFS、Btrfs、F2FS 仍须通过真实块设备身份检查；类型出现在候选表不等于已经通过生产支持验收。不存在合格目录时明确跳过 IO，不猜测 overlay 背后的宿主设备。

## 测量与复用

只创建独占 0600、128MiB 临时普通文件，预填充后执行 O_DIRECT、队列深度1的 1MiB 顺序写/读与4KiB随机写/读。每阶段3秒、重复3次，每维取较低中位数；正常退出删除临时文件。不打开业务文件、不测速裸设备、不清全局缓存、不修改磁盘调度器。自动尝试带180秒协作取消期限（36秒正式测量之外还包括三轮128MiB direct-IO预填充）；内核阻塞 IO 不能保证被 Go context 即时打断，但辅助进程独立于业务且原 supervisor 有终止/强杀界限。强杀可能遗留一个有界临时文件，禁止通配清理用户目录。

已有合法 profile 且稳定设备身份匹配时直接复用。容器/Pod ID 或设备编号改变不会触发重复测速；换盘/换节点且身份不匹配时，本地重新测量后合并新设备条目，旧条目保留并由运行时身份检查过滤。损坏、未知格式、无法读取的已有 profile 不自动覆盖。RC3 保留 v1 汇总格式；1.0 组合候选保留 v2 的三次样本及质量信息，不能直接把 v2 文件交给旧 RC2。

没有匹配基准且可见祖先已有任何有限 io.max 时拒绝测速，不临时抬高上限，也不把受限速率当成全盘基准。隐藏祖先及同设备竞争仍可能影响结果，输出基准表示该容器当时的实际观测。选一个最大的文件系统不等于所有其他磁盘都已限速；额外设备覆盖仍单独显示，不能声称整台服务器所有 IO 均已覆盖。

`automatic_io` 状态记录首次尝试/复用、选择路径、文件系统、容量、设备、profile 位置及失败原因。标定失败后的 CPU/内存按正常计划处理；坏配置或损坏已有 profile 仍按配置/计划错误拒绝，保留已有内核限额并让业务继续。默认文档不再要求手工标定；维护者可运行无参数 `crg calibrate` 重标定，旧 `--directory` / `--output` 仅保留为可选高级覆盖以兼容脚本。

## 真机路径验收任务

业务节点仅只读核对。两套原镜像在测试节点建立各自独立的隔离克隆，使用真实容器路径 `/root/start.sh`、`/opt/ccg/scripts/business-supervisor.sh`、`/opt/ccg/bin/containercacheguard`、角色独立的 `/opt/ccg/config/*.json` 及 `/opt/postgresql`。保留 `/opt/ccg` 只读挂载语义；不能把 `/lab` 占位业务检查当成真实启动链验收。新增 CRG 程序、配置和状态各容器独立，不修改正在进行24h基线的两套容器。

- P01.7：RC3 自动选盘/首次标定/复用及无权限放行；按真实路径覆盖 DBS、HISDBS 的原启动、/test、SQL、备份/同步、独立恢复和重建；原健康探针预算与失败记录保留。
- P04.1：自动标定继续使用重复采样、离散程度、稳定身份、路径覆盖；多设备及复杂存储的未测边界不变。
- P10.5：1.0 合并候选复核同一默认行为、两种模式、ID变化、只读/无盘/受限/满盘/中断、缓存/原业务共存、升级回退及文档；至少7天和既有24h+24h条件不降低。

当前状态：两个开发线已编写实现，Windows 单元/vet 已通过；Linux race/vet、真实挂载与两业务真实路径验收分别记录，尚未因此发布新版本。

依据：[Linux mountinfo](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html)、[statfs](https://man7.org/linux/man-pages/man2/statfs.2.html)、[内核 cgroup v2 IO](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)。
