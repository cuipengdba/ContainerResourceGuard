# 持续验收工具与预设条件

此文归档 P02.1/P02.2 的测试工具设计，尚未表示 24h 或 7 天已经开始/完成。源码为 [tests/vendor-soak-load.py](../tests/vendor-soak-load.py)，只能在隔离原镜像容器中显式启用。使用合成数据、原数据库参数、原缓存程序与已知 POST /test，不冒充未知厂商专用备份 API 或生产负载。

## 数据与负载

每个 DBS/HISDBS 主容器新建独立测试 schema，16,384 行，每行 4KiB 固定内容，共 64MiB payload。每两秒更新 16 行计数，每五秒 POST /test；两条独立执行线程分别采样。SQL 使用有客户端期限的异步 libpq 连接，通过 Python 标准库 ctypes 复用原镜像现有 libpq.so.5，不安装额外包；避免每次通过 kubectl exec 启动登录进程。连接、发送、收取结果遵循 [PostgreSQL 14 libpq 异步接口](https://www.postgresql.org/docs/14/libpq-async.html)，每次清空结果后再发送下一命令。API 仅访问自身网络命名空间回环地址。记录开销仍计入本容器，不声称测量零干扰。

开始计时在创建数据、CHECKPOINT 和初始摘要完成后。每次输出只写到全新目录，JSON 权限 0600，每五分钟及阶段结束落盘；只保存有界计数/延迟直方图、内容摘要和结果，不收集凭据或任意异常文本。

## 预设判定

| 项目 | 条件 |
|---|---|
| SQL/API 错误 | 0 |
| 每次请求最大用时 | 不超过 5s |
| p95 | 按直方图桶上界判断，不超过 1s；不是精确分位数 |
| 采样覆盖 | 至少预定请求数的 98% |
| 数据 | 行数、ID 合计、payload 字节及摘要前后一致 |
| 数据库进程 | pg_postmaster_start_time 前后一致，不能用容器 ID 不变代替 |
| 线程退出 | 采集线程在有界时间内退出；中断不能显示通过 |
| 基线/限额时长 | 各业务各至少实际 86,400 秒，初始化不计入 |

--test-phase baseline/enforce 不接受小于 86400 秒，acceptance 不接受小于 604800 秒；短测必须标为 smoke。程序使用单调时钟，测试不能通过修改时钟或把 60 秒结果改写为长时验收。

第二阶段可显式 --source-run-id 复用此前已通过、相同时长的数据 schema；校验此前结果及当前内容摘要，保留独立新输出。复用会保留计数变化，payload/更新范围与节奏相同；不会删除原表、重建业务库或复用旧报告冒充新时长。原业务库中其他测试数据与物理备份规模另行记录。

## 启动与采集前置条件

工具需 CRG_VENDOR_SOAK_TEST=disposable-loopback-only，且进程与当前容器 PID 1 的 cgroup 一致。外部夹具还须检查命名空间/Pod 标签、非 host namespace、非回环网络已关闭，以及原缓存进程和 Agent 的实际身份；该环境变量本身不是安全隔离机制。

正式运行前先在两种原镜像中完成短时 fresh/reuse 工具验证，并确认候选预算的备份/复制/独立恢复、辅助故障及停用恢复结果。百分比 30% 和手动 256 IOPS 候选失败均保留；不同的手动 4096 IOPS 候选两类业务共 20 项短测通过，原值/observe 的独立后续核对也通过，但原 120s 等待超时仍保留。不能自动放宽原预算。

工具准备阶段的两类错误也保留：postgres 用户不能读取私有 root fixture 目录；原镜像全局 Python 没有 psycopg2。前者改为在各自容器全新 /tmp 文件复制公开测试入口，不改变私有目录权限；后者改用已有 libpq 和 ctypes。这些是负载工具的准备问题，不是业务 SQL 或资源控制已经通过/失败的证据。原短测不会据此填成已运行。

此后 ca19975 版本的 ctypes 入口完成两种原镜像各 fresh/reuse 两轮实际 60s 短测，四轮均通过，错误为 0、相同 64MiB payload 摘要一致，SQL/API p95 桶上界满足 1s、覆盖率满足 98%。见 [短测结果](test-results-native-soak-smoke-linux-amd64.json)。该轮尚不包含之后新增的主库启动时间/数据库总大小字段与宿主周期采集器，新增部分将另做集成短测。

已开发 [宿主测试采集入口](../tests/vendor-soak-campaign.py)，尚需短测验证后才启动正式阶段。它是隔离验收工具，不是产品跨容器守护进程，不设置资源、不重启/删除业务 Pod、不向辅助程序发送信号。必须是原镜像测试标签、非 host namespace、非回环网络已关闭、两个可核对的 Agent 摘要、各自真实 cgroup 和数据挂载。正式单日阶段仅接受实际 86400 秒，七天阶段仅接受 604800 秒，短测单独标为 smoke。

采集每分钟记录各自 CPU/内存/IO、Agent/缓存进程的 CPU/RSS/写入量，固定控制值和进程身份变化、OOM kill、缓存不再 enforce 均使该阶段失败。宿主 MemAvailable 少于 8GiB 或数据盘剩余少于 20GiB 时停止自己的负载，保留失败结果。负载停止使用 pidfd 校验并只定位本次新建 Python 入口，避免 PID 复用或把业务/Agent 当成负载停止；清理不修改业务限额。

周期固定为首次第 300 秒及其后每 6h 执行一次引擎备份/流复制/独立恢复，单周期整体上限 1800s；短测第 30 秒执行一次。每次使用独立 run ID，全部内容检查通过且临时实例已停后，可显式 --cleanup-fixture 仅删除本次新建主库 schema、恢复数据库和 snapshot；保留逻辑备份/日志/报告。它不删除原业务表，不把失败现场也清掉。相同常驻合成数据可供后续 equal-duration 复用，物理库大小变化另行记录。未知厂商专用 API/真实调度周期仍列未测。

baseline/smoke 要求资源 Agent 实际 observe；enforce/acceptance 要求实际 managed/各项 applied。测试工具不自动改配额，预算须由独立显式操作预先设置。宿主采样至少覆盖预定次数的 98%，相邻样本不超过 120s。正式阶段仍需 P01 候选预算完整通过，不能用采集程序开发完成替代该前提。

集成入口可显式 --source-run-id 复用此前同容器、已通过且等时长的原生负载数据，仍产生新输出；原生入口记录全库数据库大小总计的起止值，用于解释与备份规模有关的差异。备份临时数据和周期清理也应结合这些值分析，不能把各阶段物理大小假定为完全相等。

1.0 至少七天的组合验收另有发布门槛；源代码完成、模拟时间、短测或创建标签都不能替代。当前实际状态见 [开发进展](development-status.md)。
