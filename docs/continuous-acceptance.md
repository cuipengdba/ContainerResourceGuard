# 持续验收工具与预设条件

此文归档 P02.1/P02.2 的测试工具设计，尚未表示 24h 或 7 天已经开始/完成。源码为 [tests/vendor-soak-load.py](../tests/vendor-soak-load.py)，只能在隔离原镜像容器中显式启用。使用合成数据、原数据库参数、原缓存程序与已知 POST /test，不冒充未知厂商专用备份 API 或生产负载。

## 数据与负载

每个 DBS/HISDBS 主容器新建独立测试 schema，16,384 行，每行 4KiB 固定内容，共 64MiB payload。每两秒更新 16 行计数，每五秒 POST /test；两条独立执行线程分别采样。SQL 使用有客户端期限的异步 libpq 连接，避免每次通过 kubectl exec 启动登录进程；API 仅访问自身网络命名空间回环地址。记录开销仍计入本容器，不声称测量零干扰。

开始计时在创建数据、CHECKPOINT 和初始摘要完成后。每次输出只写到全新目录，JSON 权限 0600，每五分钟及阶段结束落盘；只保存有界计数/延迟直方图、内容摘要和结果，不收集凭据或任意异常文本。

## 预设判定

| 项目 | 条件 |
|---|---|
| SQL/API 错误 | 0 |
| 每次请求最大用时 | 不超过 5s |
| p95 | 按直方图桶上界判断，不超过 1s；不是精确分位数 |
| 采样覆盖 | 至少预定请求数的 98% |
| 数据 | 行数、ID 合计、payload 字节及摘要前后一致 |
| 线程退出 | 采集线程在有界时间内退出；中断不能显示通过 |
| 基线/限额时长 | 各业务各至少实际 86,400 秒，初始化不计入 |

--test-phase baseline/enforce 不接受小于 86400 秒，acceptance 不接受小于 604800 秒；短测必须标为 smoke。程序使用单调时钟，测试不能通过修改时钟或把 60 秒结果改写为长时验收。

第二阶段可显式 --source-run-id 复用此前已通过、相同时长的数据 schema；校验此前结果及当前内容摘要，保留独立新输出。复用会保留计数变化，payload/更新范围与节奏相同；不会删除原表、重建业务库或复用旧报告冒充新时长。原业务库中其他测试数据与物理备份规模另行记录。

## 启动与采集前置条件

工具需 CRG_VENDOR_SOAK_TEST=disposable-loopback-only，且进程与当前容器 PID 1 的 cgroup 一致。外部夹具还须检查命名空间/Pod 标签、非 host namespace、非回环网络已关闭，以及原缓存进程和 Agent 的实际身份；该环境变量本身不是安全隔离机制。

正式运行前先在两种原镜像中完成短时 fresh/reuse 工具验证，并确认候选预算的备份/复制/独立恢复、辅助故障及停用恢复结果。百分比 30% 的 IO 候选已出现临时备库退出超时，不能直接当作通过的持续运行候选；另行明确测试手动预算，不能自动放宽原预算。

正式执行还需宿主侧有界采集器：记录阶段起止、各自 cgroup 实际值/CPU/内存/IO、Agent CPU/RSS/写入量、原缓存进程、Pod 身份及节点余量；输出采样不能变成跨容器产品守护进程。备份/复制/恢复按预设周期插入，先验证新入口，覆盖关键高峰；未知厂商真实调度周期继续列未测。主机保护阈值、备份周期与清理政策须在正式执行前一并冻结，当前没有把尚未开发的采集器写成已实现。
