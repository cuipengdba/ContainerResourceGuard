# 宿主容量与环境检查（v0.5 开发中）

分支 `next/environment-checks`，尚未发布。对应 P06.3 的容量来源实现；完整重启/内核/架构矩阵继续验收。

原有 cgroup 发现、与容器 PID 1 归属一致性、真实 cgroup2 文件系统、非宿主根目标、目录 inode 锁及重启身份规则不变。新检查只读容量来源，不启用控制器、不重挂载、不操作父组。

## 不把虚拟容量误认为整台服务器

CPU 默认读取 `/sys/devices/system/cpu/online`，内存默认 `/proc/meminfo`。新增 Linux 文件系统类型核对：CPU 来源必须是原生 sysfs，内存来源必须是原生 procfs；LXCFS/FUSE 或普通磁盘文件不视为可信宿主总量。

若提供只读的 `/host/sys` 或 `/host/proc` 挂载，则优先读取对应宿主路径，并做同样校验。不接受一个普通文本快照文件冒充 procfs/sysfs。挂载仍需在原部署中明确配置，CRG 不自行挂载。

不可信、无法读取或格式损坏的维度记为未知，并在 `environment.capacity_warnings` 解释。百分比模式跳过该维度；其他已知维度继续计算。未知内存时也不推导 memory_high 与总百分比的关系。手动绝对限额仍可计算，并受当前 cgroup/祖先/原值约束。

容量检查失败与 cgroup 身份失败分开：容量来源异常不能阻止对已确认的自身目标执行 status、disable、restore；身份不明仍拒绝全部控制写入。源文件系统类型只能在可信容器/挂载配置下提供依据，不是对容器 root 的安全边界。

## 当前支持证据与待测项

- 当前实机为 amd64、Linux 5.14、cgroup v2、containerd、单 XFS/LVM 数据设备。实际版本及资源/重启结果见对应报告。
- 新增单位/重复 MemTotal/数量溢出、虚拟容量、显式宿主来源失败、手动模式继续可用的单元测试；Linux 额外核对普通文件被拒绝、原生 proc/sys 文件可读。
- 该节点没有 `/proc/pressure/*` 全局 PSI 接口。不可把可选 PSI 逻辑或单元样本描述为本机所有 PSI 指标已实测。
- 6.x 内核、arm64 真机、多种运行时/namespace、节点重启和连续路径复用仍待测。交叉编译不表示真机通过，不扩大稳定支持范围。

这些检查也将进入后续诊断与支持矩阵。版本发布与生产接入分别记录。
