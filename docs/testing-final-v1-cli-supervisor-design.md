状态：设计归档，尚未冻结执行程序、上传或启动；不得算作已通过。对应原任务 P07.1、P08.1，其他任务不顺带勾选。

使用已经固定的最终 ELF 和原 DBS/HISDBS 镜像、启动链及挂载路径。前置条件是上一轮二进制维护取得准确终态、归档，所有登记 PID/start、namespace、父叶 cgroup 独立确认消失。保留旧七天测试及其数据，不重启其他夹具。沿用原手动参考配额，不以此覆盖默认20%性能失败。

## CLI 状态

1. 在原生600秒 SQL/API 测量中调用实际 crg status 的 JSON 和 human 格式。逐项核对 mode、state、cgroup、独立百分比/手动额度、实际控制值、文件身份、快照年龄及 writer_lock_held；只比较两次采样之间应稳定的值，内存计数不要求原子一致。
2. quiesce 后检查实际 Agent 已退出、写锁已释放、内核限额和恢复记录仍在、业务 PID1/PG/缓存身份不变。自然等待原快照超过300秒，再核对 JSON/human 如实显示增长的年龄与 false 写锁。当前实现提供年龄与锁状态，没有自动标记 stale 的布尔字段，不虚构字段，也不改写 TimeUTC 或 mtime 假装时间经过。
3. 重新 enable 后核对只有一份相同最终 ELF Agent、writer_lock_held=true、新快照时间及同一配额。全部在线动作和等待必须落入本轮成功的原600秒测量；不能复用先前已通过的时间。
4. doctor/preflight 的 human 与 JSON 核对自身目标、主机容量与请求；手动模式没有标定 profile 时如实保留不可用，不借用别的容器 profile。只读命令不改 config、profile、journal 或内核控制。

## 启动脚本安装工具

1. 仅操作容器私有 /recovery 目录中的副本。实际运行的 /opt/ccg 只读文件、原 start.sh、PID1、业务与缓存均不替换、不执行副本，不启动第二份 DBS/HISDBS。
2. 使用源码单元测试中的明确支持模板分别覆盖 shutdown 的 `|| :` 与 `|| true` 两种结尾。原厂私有脚本只在私有目录复制，先核对已知摘要；若不符合支持布局则接受明确拒绝且零改动，不能猜测模板或临时放宽匹配。私有脚本、环境和备份内容不得进入公开证据。
3. plan 校验源/辅助脚本/ELF 的受信摘要、原配置以及 bash -n；验证 plan 不改文件、不创建备份。活动 Agent 持有锁时 install 应拒绝，目标、状态、额度不变。
4. quiesce 后 install 支持模板副本，核对建议摘要、保留业务/缓存锚点、模式保持及私有0600备份。未知源摘要、未知布局、路径别名或重复集成应拒绝；分别保存准确退出码和原始错误，不能仅凭源码推断错误文本。
5. 仍有自有资源 journal 时 uninstall 应拒绝。完成本轮原600秒后显式 disable，确认八项运行时原值和空自有 journal，再测试成功 uninstall、原脚本字节与模式恢复。该合法卸载属于测量后的清理阶段，不能声称发生在在线600秒内。
6. 错误辅助程序不影响业务的运行事实需独立观察。副本仅 bash -n 不能代替真正启动链 fail-soft 验证；已有原启动链证据保留其准确来源。

## 冻结与验收

正式运行前独立固定新 namespace、output、run-id、程序/计划/输入摘要、每角色主检查数、内部子检查数及异常清理记录；原 SQL/API 零错误、5秒最大延迟、p95桶上界1秒、98%覆盖率、64MiB内容及原进程身份标准保持。额外安装动作不能改变配额或放宽等待。若使用 SQL/API 维护范围，则既有真实备份/同步/独立恢复结果作为单列前置证据，不能虚构本轮再次执行。

预检和执行应共用实际只读前置守卫，启动程序必须先保存排他 guard，完整记录唯一 runner 的 PID/start/入口；记录作用域变量取 gate 中的实际值，不再次引入1506启动记录 NameError。观察报告写入中可能短暂不完整，观察失败原件保留，只读重读不能触发重跑。

每个结果保留准确原件、摘要、独立复算、原600秒的时间包含关系和自有对象清理。失败不自动重试、不覆盖旧报告。没有这些结果时 P07.1/P08.1 保持待验收。
