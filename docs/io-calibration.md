# IO 标定与百分比

IO 没有固定的“总资源”标量。设备、请求大小、队列深度、读写混合、缓存、文件系统和其他业务都影响结果。本项目采用用户选定的语义：**对明确测试方法的实测基准取百分比，设置 BPS/IOPS 硬上限**。

## 方法

`crg calibrate --directory /data --output /etc/crg/io-profile.json` 必须显式执行，通常在节点维护窗口、宿主环境中进行。不要在已经受限的容器里标定，否则结果包含它原有的限制。

在所给现存目录创建独占临时普通文件，大小 128 MiB，预填充后执行同步 direct IO：1 MiB 顺序写/读、4 KiB 随机写/读，队列深度 1，每阶段默认 3 秒。测量速率保存为基准，不把它称为全盘极限性能。写入包含文件系统与设备缓存的实际影响，不承诺断电持久写性能。

不用 fio 或其他运行时依赖；使用 Linux O_DIRECT 和页对齐缓冲区。平台/文件系统不支持时报告失败，不回退到会被页缓存污染的测速。拒绝 overlay 和 tmpfs，拒绝可用空间不足 384 MiB 的目录。不会测速裸设备、修改数据库文件、清理全局缓存、修改磁盘调度器。

基准必须经维护者接受后才分发给业务容器。生产启动、定时循环绝不自动测速。

## 设备身份

profile 同时保存初始 major:minor 和基于 DM UUID / WWID、容量、分区信息的稳定摘要。运行时检查身份；编号变化时按稳定身份重新匹配，缺失/歧义时跳过 IO。

只有 major:minor 而无稳定设备身份不足以安全跨重建应用，程序会拒绝标定。更换设备、扩容、迁移节点或工作负载基准变化后需要重新标定。

LVM/设备映射栈可能在逻辑设备和物理盘上同时出现统计。默认针对数据挂载所在的块设备配置，不在同一栈所有层级重复设置。应通过实际 IO 测试确认该层的限制有效。

RC2 检查 profile 里设备间的上下层/分区父子关系，重叠或无法确认关系时跳过相关设备。设备 UUID/WWID 变化、缺失或歧义时不套用旧基准；编号变化的重匹配有自动测试。基准时间不等于有效期证明，设备性能或负载条件变化后仍须维护者明确重标定。

## 多个设备

每个独立数据设备各执行一次标定，使用同一个输出 profile（同设备替换、不同设备合并）。三个资源仍只填一个 percent；新增设备不要求手填四个限速参数。

容器只应用 profile 中自己当前可识别的设备。profile 应只分发该容器实际使用的设备；不扫描其他容器，不自动猜测未来可能访问的所有磁盘。未纳入 profile 的设备没有该项自定义硬上限，状态与运维检查须据此评估“整个容器 IO”覆盖范围。

可选 `data_paths` 让预检/状态列出容器内路径的文件系统设备与是否已有计划限额；它不新增资源参数，也不自动扩展设备管理范围。详见 [本地运维](operations.md)。

## 解释测试结果

读 BPS / 写 BPS / 读 IOPS / 写 IOPS 同时受限，实际吞吐由其中更严格的维度决定。例如顺序读可能先碰到 BPS，随机读可能先碰到 IOPS。允许内核短时突发，长窗口观察才能验证限速。

限制的是该组记账的块 IO；页缓存命中、网络流量、NFS 请求不能直接按磁盘 IO 计算。缓冲写入归属依赖文件系统 cgroup writeback，多个容器写同一 inode 也可能影响归属。见 [内核说明](https://docs.kernel.org/admin-guide/cgroup-v2.html#writeback)。
