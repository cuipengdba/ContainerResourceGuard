# 旧observe程序首次接入与独立恢复演练计划

第19轮[冻结计划](test-plan-observe-first-adoption.json)覆盖原DBS/HISDBS镜像的两种路径：基线夹具`/crgfixture`/`/crgstate`，以及真实接入`/opt/ccg`/`/opt/crg`/`/etc/crg`与各自缓存状态路径。均保持原PG数据目录、8960MB参数、原启动脚本及缓存配置；等第35组开销测试终止、namespace独立确认清理后才顺序创建四格。原24h基线不改。

旧程序是确切fc2e26d observe程序，缺少新在线协议声明；候选是确切d6ea657未发布组合程序，固定手动7.2核、20001980416B、读写64MiB/s与4096IOPS。**不调用或绕过binary-install协议预检**。这是先停用并验证真实原值、再显式首次接入的演练，不是保留限额在线升级成功。

每格先运行原生64MiB SQL/API600秒，在完整计时内用旧程序disable、确认无写入者和实际原值、私有备份，再原子替换本夹具程序/配置。保留同一自动重试helper，由enable恢复唯一候选Agent；只三项限额、日志与不变profile核对后至少保持120秒。随后用单独保存的**确切旧程序参考入口及其旧配置**停用兼容三项journal并恢复真实原值，再恢复旧程序/配置与observe。全程不导回/删除journal，不另起helper，不重启业务或缓存。

二进制/配置由宿主显式原子替换只作用于本轮私有夹具，容器原只读挂载保持；不能据此宣称产品可自动写任意只读部署。备份为私有证据，不作为覆盖活动状态的恢复快照。任一不兼容、锁冲突或实际值异常均保留失败，不能强制迁移。

原生零错误、最大5秒、p95桶上界1秒、98%覆盖、数据和PG进程不变、线程正常结束均保持；300秒启动、缓存45秒且总启动300秒、实际进程/控制身份和OOM条件不放宽。该600秒横跨observe/接入/回退，只证明所列来源和路径的业务连续性，不替代完整600秒限额、24h+24h、七天或两个已发布次版本的门槛。
