## 已确认的结果

[上一轮完整测试](testing-full950-bytecode-export-fixed.md)的32项业务和30项独立检查全部通过，但两角色原工厂仍判诊断失败。其清理和导出已成功，原业务退出码均为0。源码显示业务方法关闭日志后清空`self.worker`，包装器随后才执行`Observer.finish()`；旧复合检查却要求该字段非空。这是源码控制流定位，没有伪称采样到了上一轮finish瞬间的字段值，旧失败原件不改判。

修复在精确匹配原native命令的一次真实`Popen`返回后保留该子进程对象，结束时只查询此对象的退出状态。原`Popen`异常原样传播且不重试；捕获句柄或记录诊断失败时仍返回原业务子进程对象。业务字段被清空或替换不会改变它。重复匹配保留第一个句柄并判诊断失败；原业务子进程仍运行时不能通过退出检查，原非零退出码保留，业务成功标准仍由原业务判断。没有删除“原native已退出”的条件，也没有等待、终止或替换业务子进程。
