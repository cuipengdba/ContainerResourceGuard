# 架构与一对一边界

每容器一份进程、一份配置、一份本地状态。程序不访问集群 API，不订阅其他 Pod，不枚举容器运行时，不提供目标 PID/cgroup 选项。

## 发现

从自身 `/proc/self/cgroup` 取 unified hierarchy，从 `/proc/self/mountinfo` 获取匹配挂载的 root 与 mountpoint。支持完整宿主路径、namespace 内的 `/`、挂载根为子树及转义空格。不能简单拼接固定路径。

要求自身与容器 PID 1 的 cgroup 一致，拒绝 `..`、歧义挂载、符号链接路径和宿主机真实根组。生产发现验证文件系统为 cgroup2；宿主真实根没有 `cpu.max` / `memory.max`。不创建控制组、不启用父控制器、不移动任务。

可见的 cgroup namespace 根只有在它本身就是容器目标且内核允许写时才能控制。`nsdelegate` 等仍可能拒绝写入，即使文件权限看上去可写；状态报告实际写入错误。

## 换算与写入

CPU、内存、IO分别用独立百分比换算，默认各20；当前策略设置`cpu.max`、`memory.high`和`io.max`，IO再按设备划分条目。memory.high为允许超过的回收/节流目标。memory.max仅为外部边界读取及历史自有硬限额恢复保留写入能力，不新增硬限额；详见[内存策略](memory-reclaim-policy.md)。

先保存原值与写入意图，再写文件，回读验证，最后确认日志。原值或意图无法持久化时不执行写入。多个控制文件之间没有原子事务，部分成功时逐项报告。

每轮验证 cgroup 的启动标识、路径、inode 身份。重建后重新发现，旧日志归档为 `journal.previous.json`，不拿旧容器原值套新组。

## 独占与外部冲突

RC2 先独占锁定自身 cgroup 目录 inode，再锁状态目录。同一 cgroup 使用不同 state_dir 或不同挂载别名仍会竞争同一个内核目录锁；不依赖容器 ID 文件或 PID 猜测。两个容器的 cgroup inode 不同，各自独立运行。仍需沿用原状态目录保存恢复依据。

每次写前比较当前值与最后一份自己写入的值。外部变化时暂停该项，记录冲突，不能与 kubelet/运行时反复争写。配置百分比不会更改 Pod 的 resources 声明，调度器也不会知道内部新限额。

写入意图同步完成后再次读取控制值；若等待磁盘期间值已改变，则保留外部值。检查与实际 write 之间仍存在非原子窗口，不能替代部署方明确资源管理归属。

## 停用与恢复

收到 TERM/INT 后停止循环，默认保留已写限制。停止 Agent 后执行 `restore`；若当前仍等于其最后写入值或未完成的写入意图，恢复原值并回读。若外部已改变则保留外部值。

RC2 的 disable 先写入绑定当前身份的停用标记，Agent 在独立的 1 秒控制检查中退出；disable 取得相同目录锁后恢复。enable 只删除标记。详见 [本地运维](operations.md)。损坏标记不能被当作“已启用”忽略。

崩溃发生在写入与日志确认之间，可通过保存的 pending intent 判断本次写入是否已完成。恢复失败会明确报告；不能承诺异常退出时立即自动解除限制。

状态文件是诊断快照，不是恢复依据。未变化时每 5 分钟刷新，变更时按检查周期刷新；journal 仍在每次控制修改之前同步保存。原子 JSON 写入必须完成文件同步、rename 和目录同步，失败不会被静默视为成功。

## 降级

支持缺权限、只读文件系统、缺控制器、缺基准、内存保护跳过、外部冲突和状态目录不可写的可观测处理。辅助程序退出不能驱动业务退出，这由 supervisor 层保证。

依照 [Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html) 实现。实时调度类、网络带宽、共享缓存跨组归属和文件系统不支持 writeback 的情况不在普通数据库容器 CPU/IO 硬上限的完整覆盖承诺内。
