# memory.high 发布程序的真实路径业务复验

[冻结计划](test-plan-memory-high-business.json)验证 preview.4 的真实发布程序，来源及两次新检出重建见[身份记录](test-results-memory-high-identity.json)。四格原生 88 项、14 项包完整性检查、测试节点 AMD64 身份及八文件重建一致性均须先通过；新版自身三场景各 1800 秒开销必须终态通过、exit0 且命名空间独立确认不存在，才能创建业务 Pod。准备期间只等待该门槛，不提前启动业务。

使用测试节点 DBS/HISDBS 原镜像、原 start.sh、原 PG 参数、原 CCG 只读挂载和真实容器内目录。每个业务容器各有独立 Agent。使用新的私有背板、DCS、凭据与 64MiB 合成数据；先断开测试 Pod 的外部网络，再释放启动门禁。

CPU 7.2 核、读写各 64MiB/s 和 4096IOPS；内存目标按用户新要求设 memory.high=20001980416B，运行时原 memory.max=20GiB 保持。其他五项实际控制保持原值。两角色顺序各运行 600 秒，保留原总启动 300 秒、缓存观察 45 秒、零 SQL/API 错误、最大 5 秒、p95 上界 1 秒、覆盖 ≥98%、主库不重启、负载完整性及十项备份/同步/独立恢复内容与清理标准。每日 0600 日志需记录 v2 与 high-reclaim-throttle。

该命名手动预算通过也不能证明默认百分比预算、长期、ARM64 厂商真机或物理多盘已通过。旧硬策略的业务记录单独保留，不计入新程序。本次已冻结，尚未创建业务 Pod。

等待协调器已启动，独立观察确认其处于新版开销终态门槛等待、业务命名空间不存在；尚无业务通过结论。
