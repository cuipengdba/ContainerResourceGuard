# 开销验收预设

2026-11-10，承接 P07.4/P09.4。以下先冻结判定，尚未表示 30 分钟已完成。测试代码与原始输出保存在授权测试节点的私有工作目录，公开报告只包含去标识数值。

同一 cb7b37f 开发二进制，三份独立占位容器各一份 Agent：健康状态、指标/事件输出指向受保护文件的符号链接故障、只读 cgroup 写权限故障。三组启用 metrics/events、15s 周期；先完成初始化并预热 45s，再实际计时至少 1800s，每 10s 记录自身 Agent CPU、RSS、write_bytes/wchar、状态修改时间和自身 OOM kill。它不是 DBS/HISDBS 延迟或 24h 验收。

固定 IO 为读写各 64KiB/s、各 8 IOPS。只读组的这项约束由测试夹具预先对**自己的真实叶组**设置，并核对实际只读挂载；不能把它当作 Agent 在只读挂载内有写权限。其余组由各自 Agent 设置并回读。均有独立运行时 CPU/内存保护，节点 MemAvailable 低于 8GiB 或空间低于 20GiB 即失败并清理自建容器。

| 判定 | 预设上限 |
|---|---|
| 单核平均 CPU | 0.1% |
| 采样 RSS 最大值 | 20MiB |
| 稳定状态写入间隔 | 至少 299s，允许 1s 观测容差；必要 journal 不省略 |
| Agent write_bytes 增量 | 健康 ≤8MiB，故障 ≤16MiB /30min |
| OOM kill | 无新增 |
| 身份 | 同一 Agent start ticks，占位 PID 1 一直存在 |
| 输出故障 | 受保护标记不变，导出 unavailable；资源协调继续 |

write_bytes 是该 Agent 的 /proc/PID/io 计数，不代表整节点物理写放大或其他辅助程序开销；CPU 不包括外部夹具。每分钟指标写入与状态每五分钟写入分别核对，不能把两种文件混称。

首个三组夹具在只读组启动阶段超时，正式计时没有开始，另外两组未生成测量样本；已清理该批 namespace，失败记录保留。后续修正只读挂载与命名空间的对应关系，使用新目录、同一二进制及原判定重新执行，不把夹具重试写成产品修复或已达标。


## 实际结果

同一二进制按上述原判定实际测量 1800.025s，三组各 181 个样本，全部通过；自建 namespace 确认已移除。结果只适用于本次 Linux 5.14 amd64、cgroup v2 占位业务，不代表 DBS/HISDBS 长期业务验收。

| 场景 | 单核平均 CPU | RSS 采样最大 | Agent write_bytes 增量 | 最小状态写入间隔 |
|---|---:|---:|---:|---:|
| 正常协调 | 0.01556% | 6684672 B | 135168 B | 300.001s |
| 指标/事件输出故障 | 0.01556% | 6094848 B | 20480 B | 300.001s |
| 只读 cgroup | 0.02500% | 6488064 B | 1114112 B | 300.108s |

各组均保持同一 Agent 进程、无新增 OOM kill；输出故障标记不变、导出 unavailable、资源协调继续。必要的失败写意图仍持久化，所以只读组写入量较高。详见 [脱敏数值与摘要](test-results-overhead-30min-linux-amd64.json)。这关闭本环境的 30 分钟工程判定，其他负载/内核/架构仍需分别测试。
