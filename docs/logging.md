# 每日日志与自动清理（R27）

当前RC3与1.0组合开发线的`crg run`默认记录运行日志，无需额外配置：

```text
/var/log/crg/crg-2026-11-10.log
/var/log/crg/crg-2026-11-11.log
```

按容器本地日期（`/etc/localtime`或TZ）每天一个文件，同日重启追加同一文件。JSON Lines含时间、级别、事件和有限详情，记录启动、资源状态变化、自动标定准备/结果、正常退出及错误；安静运行每5分钟心跳。CLI原机器JSON保持在stdout，运行日志同时写stderr，便于容器日志采集。

- 保留今天及前29个日历日，30天前日志删除；启动、写日志及至多每分钟检查清理，空闲Agent也在跨日时创建当天文件。
- 所有受管理日文件的总大小上限为**1GB=1,000,000,000字节**，先删最旧文件；只剩当天文件仍超限时清空当天旧内容，写清理标记后继续。不会生成当天`.1/.2`分片，仍一天一个文件。
- 仅操作专用目录下严格匹配`crg-YYYY-MM-DD.log`的有效日期普通文件。其他业务文件不清理；符号链接、硬链接、FIFO等不作为可写日志目标。Linux逐级目录FD、nofollow、非阻塞文件打开及短持有日志锁防止重定向/阻塞。
- 日志目录默认新建0700、文件0600；现有专用目录不可组/其他用户可写。每容器独立目录，不共用同一日志卷目录。隐藏锁文件`.crg-logs.lock`不是日志文件。
- 目录只读、无权限、磁盘满、写入或清理失败，报告`file_logging_unavailable`并继续stderr输出，不把日志错误变成资源控制或业务启动的失败；重复相同文件错误最多每5分钟提示一次，恢复后提示。正常资源控制逻辑照常执行。
- 单条结构化记录最大64KiB，超大详情改为省略标记；不记录完整配置、环境变量、命令行、业务SQL、业务文件内容或凭据。日志中容量/控制结果和错误路径仍应按私有运维数据管理。

如需更换目录，可选`{"log_dir":"/data/crg-logs"}`或`--log-dir /data/crg-logs`，无须设置保留天数/大小。相对或不安全路径只使文件日志降级，不拒绝资源预算；旧版不识别新增字段。组合候选可随有效配置重载切换日志目录，CLI指定时持续优先。

要在Pod重建后保留30天日志，给该容器挂载独立持久目录；容器可写层/emptyDir随Pod删除时不能凭程序恢复旧日志。本程序只清理自己的日文件，不修改原缓存/DBS/HISDBS日志和Kubernetes节点日志策略。此前有界events.jsonl是独立诊断功能，不能替代这套每日日志，也不因events_enabled=false而关闭本功能。

实现及本地测试已接入；Linux只读/磁盘满、跨日、真实1GB稀疏文件和业务不中断等实测结果另行归档，不提前当作已通过发布门槛。
