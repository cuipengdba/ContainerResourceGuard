## 预算与判定

在新建隔离原镜像 Pod 中执行初始化，再备份并保留数据重建 Pod。原 start.sh 和数据库参数保留；资源、缓存辅助程序独立启动，不等待资源程序就绪。非回环网络先由测试夹具关闭。每个 Pod 外部保护为 CPU 8、内存 20GiB。

三次显式 IO 标定取各维度较低中位数；启动和 Agent 循环没有测速。为了兼容本次 RC3 源码，保留完整 v2 样本证据后，将中位数写成 v1 profile。该组样本波动较高：读 BPS 43.69%、写 BPS 69.73%、读 IOPS 43.52%、写 IOPS 18.35%。它只是这次明确方法和时段的测试基准，不是设备物理峰值或生产标定推荐值。

| 模式 | CPU | 内存 | 设备读/写 BPS | 设备读/写 IOPS |
|---|---|---|---|---|
| observe 20% | 仅计算 | 仅计算 | 仅计算 | 仅计算 |
| enforce 20% | 4.8 核 | 13,334,654,976B | 7,649,691 / 5,077,704 | 21 / 21 |
| enforce 30% | 7.2 核 | 20,001,980,416B | 11,474,536 / 7,616,556 | 32 / 32 |

20%/30% 都在实际 cgroup 中写入并回读确认，没有临时放宽额度或跳过 IOPS。percent 对应整个容器共享预算，辅助进程和管理命令也在该预算内。

测试前预设 SQL/API 就绪期限 300s，取自业务节点现有 liveness 的首次延迟。这只是本次工程验收条件；现有实际探针是 exec `ls`，initialDelay=300s、period=120s、timeout=300s、failureThreshold=3，没有 startup/readiness probe。**ls 成功不证明数据库就绪，也不能把本次 SQL/API 超时直接写成原探针失败。** 原业务节点只读查看，未调整探针或部署。

## 后续处理

HISDBS 后续相同矩阵已完成，见 [JSON](test-results-cold-hisdbs-linux-amd64.json)：observe 初始化约 20.32s、备份后重建 23.92s；enforce 20% 在 300.79s 内未就绪；enforce 30% 初始化 249.83s、备份后重建 204.03s。三类限额均核对实际值，本次所有 ls 检查均成功，包括 SQL/API 未就绪的 20% 场景；未采集到 CPU 节流或 memory.events OOM。测试 Pod 已移除。

只读检查原镜像入口可见：它会在启动时重新解压数据库程序目录，复用挂载数据目录仍产生大量写入。HISDBS observe 重建的设备计数约 692MB 写入，因此不能把“不是首次建库”理解为几乎没有 IO。结合限额值、CPU/内存计数与 IO 等待，瓶颈指向受限的原解包路径。没有为缩短启动时间改原解包逻辑。

另做一组 DBS 全新初始化 [同配额对照](test-results-noagent-control-linux-amd64.json)：先在自身容器内用 run --once 完整写入相同 30% 控制值，命令退出后再启动原业务，常驻 CRG 路径设为缺失。一次性施加耗时约 0.58s，不计入就绪时间；SQL/API 约 251.90s 就绪，接近常驻 Agent 的 250.51s。实际预算相同、无常驻 crg 进程、CPU 无节流及 memory.events 无 OOM 均核对，测试 Pod 已移除。这支持主要延迟来自额度下的启动 IO，而非必须等待 Agent 就绪；只有一组对照，不能给出统计性能保证。kubectl exec 超时只终止客户端，可能仍给容器带来管理命令开销；所有这些探测都计入容器预算，后续需补充低干扰探测。

这些重建沿用挂载数据目录，但 HISDBS 本轮没有跨重建行标记，不能单凭目录复用证明行数据持久化。DBS 的独立补测已完成，见 [JSON](test-results-cold-dbs-recreation-linux-amd64.json)：30% 下复用前轮隔离数据，SQL/API 约 205.20s 就绪；写入 128 行标记并完成逻辑备份，再次重建约 211.25s 就绪。标记行数和合计前后均为 128/8256；新身份不同、旧 journal 已隔离，实际预算仍保持原值，测试 Pod 已移除。此结果不覆盖首次超时，也不替 HISDBS 补上未做的行标记验证。

当前证据说明低 IO 额度会显著拖慢初始化，不能承诺原业务在任意 20%/30% 下保持原启动时间。可选择合适总百分比或用手动模式明确各项预算；本程序不会自动替用户扩大额度。正式安装前仍须完成适合目标负载的数据规模、标定质量与就绪验收。
