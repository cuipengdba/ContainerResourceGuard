# IO 控制与标定工具（v0.3 开发分支）

适用分支 `next/io-controls`，基于尚未发布的热重载开发分支；尚未发布 v0.3，也不表示 RC2/RC3 接受新字段。当前改动对应 P04.1/P04.2/P04.5 的实现部分，复杂设备实测和全部发布条件继续保留。

## io_weight

两种资源模式均可添加 `"io_weight":200`。范围 1–10000，省略不改。只修改自身 `io.weight` 的 `default` 权重，保留管理员已有的每设备覆盖；不改根 cgroup、不开启宿主机 IO cost 控制器、不切换调度器，也不退回修改 `io.bfq.weight`。

它是相对优先级，需要对应 IO 权重控制器实际启用，并受设备覆盖及父层分配影响。成功回读只证明默认配置写入，不证明吞吐按权重比例分配。IO 硬上限仍由 `io.max` 的 BPS/IOPS 控制；总百分比语义不变。接口不存在或格式不支持时仅跳过这一项，其余控制与业务继续运行。

原值日志只记录默认行，恢复时保留每设备覆盖；外部改变默认权重则报告冲突。重载明确删除 `io_weight` 时尝试恢复原默认权重，observe 不恢复。

接口语义依据 [Linux cgroup v2 官方文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)。

## 重复标定与 profile

```sh
# R26：默认后台首次自动执行；此命令用于维护者主动重新标定。
crg calibrate
crg profile-check --io-profile /etc/crg/io-profile.json

# 默认只生成预览，不写文件；相同稳定身份默认拒绝覆盖。
crg profile-merge --io-profile /tmp/a.json --merge-profile /tmp/b.json
# 显式替换并写入指定文件。
crg profile-merge --io-profile /tmp/a.json --merge-profile /tmp/b.json --replace --output /tmp/merged.json
```

每次样本仍使用新建的 128MiB 普通临时文件，不读业务文件、不写裸盘、不清全局缓存；每个样本结束删除该临时文件。`samples` 为 1–9，默认 3，`seconds` 为每阶段 1–30。包括每次初始化写入，整体耗时可能大于 `samples × seconds × 4`；IO 阻塞不能假装可被 Go context 立即中断。R26新增首次辅助Agent自动标定/复用，业务不等待；协调循环不测速。

新标定输出 profile v2：保存各样本四维速率、阶段时长和时间戳，汇总采用每维中位数；偶数样本采用较低中位数，不选最快一次。每轮和结束时复核设备身份，变化时拒绝结果。读取源文件有 1MiB 普通文件上限。

`profile-check` 显示稳定身份解析、样本数和 `(最大值−最小值)/中位数` 离散程度。少于 3 次样本或某维超过 25% 时提示质量不足；提示不是对物理性能的保证。超过 30 天建议重新评估，时间过期不会自动测速或扩大限额。方法、竞争、设备和工作负载变化会改变基准。

v1 profile 继续可读，可合并到 v2；导入旧设备条目没有样本时明确提示未知离散程度，不编造历史样本。v2 的汇总与样本中位数不一致、重复稳定身份、零速率、未知方法均拒绝。profile 合并是文件维护操作，不改变当前内核限额；需等待协调或显式 reload 才重新计算。

旧 RC2/RC3 不支持 v2 新字段。降级前备份 profile 并使用旧版本可读取、对该节点有效的 v1 基准，先用新版本核对恢复和 journal 兼容性；禁止删日志后用无限值覆盖。设备编号变化仍按稳定身份重识别，替盘身份不匹配时，新自动流程在无已有IO上限等前提下生成本地基准，不复用旧设备性能。新机器应本地标定，不能因为文件可解析就直接套用另一台机器的性能。

## 当前验证范围

已加入默认权重所有权/每设备覆盖保留、外部默认冲突、缺接口、参数边界；以及中位数、离散程度、取消、样本间替盘、显式合并与旧数据质量标识测试。Windows 通用单元与 vet 通过。Linux、真实 io.weight、重复标定文件清理、真实多设备/映射栈和权重竞争效果尚需验收，不能把可回读视为调度效果已验证。
