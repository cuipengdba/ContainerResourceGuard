# 有界事件与指标故障隔离实测

2026-11-10，源码 f7b4a560fddc4c98eb027964c2a434a6dff98849。[该源码 CI](https://github.com/cuipengdba/ContainerResourceGuard/actions/runs/42700896486) 通过；测试节点 Go 1.22.5 的 Linux race/vet、建模强杀和两组脚本故障回归通过。二进制摘要及全部 17 项真实检查见 [JSON](test-results-events-linux-amd64.json)。

独立占位容器中，events 与 metrics 默认不生成文件；显式启用后文件权限为 0600，内容未带入容器 ID/cgroup 或业务路径，均受体积限制。分别把指标/事件路径替换为指向受保护标记的夹具符号链接，导出拒绝，标记未变；CPU 0.3/0.35 的资源协调仍生效，PID 1 存活。显式修复路径后恢复导出。

随后多次修改 CPU 限额，在真实墙钟一分钟内事件文件未逐次更新；观察超过 63 秒后，文件出现合并后的新状态及非零 coalesced_changes，记录数及体积仍受限。受控停用恢复真实 CPU/内存原值，最后指标与事件文件保留，命名空间确认消失。

这 17 项包含既有指标功能在新二进制上的回归，不是全部都是新增事件场景。未设置低 IO 限额，也不是 30 分钟开销或长期异常证据。64 条保留上限、坏文件不覆盖、失败限频及静态状态不写有单元证据；后续真实低 IO/长时结果单独归档。
