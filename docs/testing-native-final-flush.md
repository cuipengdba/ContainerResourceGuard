# 原生负载提前失败的最终诊断清理资格

[实际结果](test-results-native-final-flush-qualification.json)：宿主 18 项及 DBS/HISDBS 两镜像各 8 项通过，隔离执行器退出 0。它证明专属测试负载可以在外部失败后正常终止并写出部分诊断；尚未将此路径接入新一轮完整压力执行器，原 R203 的失败和诊断缺口仍保留，未宣称业务问题已修复。

## 身份、错误和时限

`tests/vendor-native-session.py` 是隔离验收工具，单个 Session 只绑定一个本轮原生 worker。它逐项核对所在 cgroup、唯一候选、完整固定参数、run-id、源码摘要、可执行文件摘要与 PID/start_ticks，再打开 pidfd；发 TERM 前重查同一身份，依靠 pidfd 避免 PID 重用。只接受固定 smoke 参数，不使用进程名匹配、进程组信号或整组终止。

仅当调用者已有明确业务异常时允许 `finish_after_failure`，正常成功不走提前终止路径；原异常对象继续优先。清理最多 120 秒，不强杀、不重试、不延长原 600 秒业务测量，不向 DBS、PG、API、Agent 或其他任务发信号。超时或身份不明保留失败/未知并交给原有 namespace 清理，不能伪装取得最终文件。pidfd 只证明该进程退出，不自行声称知道退出码。

初次 R217 在扫描到无关 `python -c` 的长参数时触发读边界，未发送信号，0 项检查；自建子进程全部回收、控制值未改。其[旧模块](test-evidence/native-session-217.py)、[旧检查器](test-evidence/native-session-checks-217.py)、摘要和失败结果均保留。修正为有界读取并跳过超过 8192 字节的无关参数；精确候选的固定参数有更小的长度约束，仍逐字节匹配。

R219 实际 18 项包含：同一 PID/start/cgroup/源码/可执行文件/pidfd、巨大无关参数、错误 start、错误 run-id/源码、缺业务失败、超出清理时限、重复精确候选、TERM 后最终文件、已退出不再发送信号、无响应超时而不强杀、关闭幂等以及控制值保持。仅使用自建占位子进程，不能作为 PG 业务证据。

## 两厂商镜像的实际 PG 路径

R220 创建两个新的独立 emptyDir PG 实例和 mock `/test`，使用原已资格验证的 Python2.7.5 厂商镜像、只读 bin/lib/share、非 root 999:998、512MiB/1CPU、只读根、drop ALL 和隔离网络。它不挂载或初始化原 PGDATA，不连接已部署的业务库。原 worker `50ea0454…` 与采集 helper `83b3f889…` 原字节保持，基础 PG/Pod 函数从摘要固定的 R194 源码提取。

原生负载仍请求 **600 秒**；宿主在约六秒后模拟一个外部业务异常，使用新 Session 精确发现并只向该 worker 发一次 TERM。DBS 实际测量 6.541597 秒、HISDBS 6.344204 秒；最终清理等待分别 0.581063 和 0.430548 秒。两者各有 4 次 SQL、2 次 API 和 7 个只读 PG 样本，最终诊断均落盘并按 SHA256/来源/请求计数关联，无丢弃或采集错误，原 PG 未在测量中重启，64MiB 校验及线程停止保持。

**两份原生报告均为 `failed`、`interrupted=true`。** 原覆盖率仍按 600 秒计算而不足 98%；DBS 这段短测的 SQL p95 桶为 2 秒，也未满足原 1 秒标准。不将资格测试成功理解为原生业务成功。采集 helper 内部“零信号”字段只覆盖其内部动作；外部清理实际每角色发送的 1 次 TERM 在宿主 Session 中单独记录。

各角色 8 项核对新非 root PG/空输出、部分报告保持失败、最终文件身份关联、逐类计数、真实 PG 样本、数据与原进程、未放宽原标准和零丢弃。原业务异常对象、实际控制值、只读组件摘要前后相同；自建 PG 正常停止、两个 Pod/namespace/cgroup 及宿主 runner/worker 独立确认清理。原配置、profile 原缺省状态与已发布 ELF 摘要再次核对保持。
