# 后续24小时限额阶段的前置计划

本页是P02的准备清单，**没有启动正式enforce，也没有执行器**。[固定候选、预算与条件](test-plan-enforce24h-three-resource.json)不能作为测试完成证明。旧observe基线仍须实际86400秒、四个完整备份周期及最终原生校验全部通过；12h/零错误快照不能触发切换。

候选暂选已有真实业务/故障/冷重建证据的未发布组合d6ea657二进制，固定手动CPU7.2核、内存20001980416B、读写各64MiB/s及4096IOPS。继续同一两业务容器、同一64MiB数据，显式复用已通过的等时长baseline source run；完整86400秒及原零错误、5秒最大、1秒p95桶、98%覆盖和全部内容/身份/原值条件保持。

切换前还必须在独立原镜像夹具验证**旧observe程序的首次接入流程**。旧基线程序缺少新在线安装协议声明，不能复用第15轮“两套均有声明程序”的成功结果，也不能绕过第13轮拒绝保护。须备份旧程序/配置/私有状态，用旧程序停用并验证真实原值，再按已演练的显式接入步骤原子替换，只重启被确认的Agent子进程，核对原自动重试helper、一对一writer、原业务/缓存身份以及持久日志。接入失败则不启动enforce，不删除journal来强行运行。

现阶段不修改基线任何文件、进程或资源值。阶段间Agent来源确有变化，应分别记录源码/程序/负载与周期工具摘要；不能把两阶段延迟差全部归因资源限额。手动预算的正式阶段仍不能追认默认20%业务性能，七天与硬件门槛独立继续。

正式24h enforce增加[只读前置核对记录](test-preflight-enforce24h-not-ready.json)：基线原生尚未86400秒、四周期未最终验收，首次接入四格也未结束，核对结论为not-ready。只读取已有证据，不启动负载、不改程序/配置/控制或发送信号；它不是执行器。实际切换仍须重验Pod/进程/cgroup身份、源摘要、原值、备份与宿主预留。该固定快照不替代未来终态。
