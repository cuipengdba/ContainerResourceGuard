# 私有 FIFO 接收端与完整压力工厂接线

[结果](test-results-private-fifo-receiver-factory.json)、[完整源码及原件](test-evidence/private-fifo-receiver-factory.json.gz)新增接收端与工厂接线候选。原产品仍为[preview.4](releases/v1.0.0-preview.4.md)，内存百分比用 memory.high，不新增 memory.max，外部硬上限保留；CPU/内存/IO各自百分比和默认20%、每容器一对一、无权限不阻断、v1跳过、每日/30天/1GB日志策略均未改变。

## 改动

宿主机测试诊断器在确认的原 Pod PID1 根目录中创建 postgres 所有的0700目录和0600 FIFO，复制已验证的原始 sitecustomize 模块，再启动一个专属非阻塞读取线程。每次准备、启动和清理都检查绑定身份；目录和文件以已打开的目录描述符及设备/inode校验，拒绝接管既有目录或删除额外/替换文件。此接收端属于可选验收诊断器，不是新增生产资源控制器，也不管理多个业务容器。

读取缓存最多1MiB；多读到第1048577字节即标记 incomplete、关闭读取端，保留的有界前缀不得冒充完整数据。每条最多512字节、最多1024条，拒绝末尾半行、错误前缀、错误run-id、超长或超量记录。停止有线程等待上限，关闭真实描述符，身份校验后清理自己的两个文件和目录。写端始终非阻塞；读取端不存在或已关闭时，辅助记录失败不阻断原 HTTP。

工厂候选改为通过专属 FIFO 环境变量注解唯一匹配的原 native 命令，不再从业务 stdout 解析注解。结束时先停止接收并保存独立原件，再解析、清理，最后关联原业务请求；读取完整响应的原始业务结果保持权威。候选增加通道已停止、无溢出、文件/线程/句柄清理且原 native 已退出的独立诊断检查，原六项诊断检查保留。原核心、worker、原四秒socket超时与原请求关联算法未修改。

## 实测范围

867在97节点完成15项顶层检查，全部通过。主机运行原17个工厂用例、新18个真实接收端用例和8个真实通道工厂故障用例。接收端实测覆盖正常传输、无写端EOF、缺读取端、停止后关闭、真实1MiB+1超量输入、真实EPIPE、错误/半行/超长/1025条记录、身份变化、替换FIFO、额外文件、既有目录、部分创建失败、活线程清理拒绝及真实FD关闭。

两个原 DBS/HISDBS 镜像各执行三次 postgres/Python2.7.5 真实启动：正常、未启动读取端、读取端已停止。正常各收到1条注解；另两种情况均ENXIO并跳过激活。六次原worker的--help及自有loopback HTTP均正常完成；请求体 `{}`、四秒超时、完整响应、原stdout标志保持，HTTP线程和临时目录清理完成。测试usercustomize只在自有HTTP中提供时钟，不修改实际sitecustomize源码，不是原native时间关联证据，也没有启动厂商数据库或600秒负载。

873补充9个工厂路径检查（保留前8个）。成功用例运行真实 Observer.start、哈希校验加载接收模块、创建FIFO线程、确认接收先于采集就绪、唯一命令重写及结束清理；保存、停止、导出、清理、并发proxy替换等故障保持原业务返回值/同一个异常对象。该成功用例的采集器和Kubernetes身份是模拟对象；模块加载、FIFO、线程、描述符、导出和清理是真实操作。它不等同于完整BPF/厂商600秒联调。

870的冻结单元夹具在静态检查时发现未向模拟TOOLS目录复制sitecustomize.py，已在密码输入前取消本地上传器，未建立远端连接或启动任务。原冻结计划和源码保留为“静态拒绝、未执行”；873只修正夹具拷贝，工厂、接收端和shim与867完全相同。没有把未执行计划记为通过，也没有运行已知缺件的夹具。
