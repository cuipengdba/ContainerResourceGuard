# 有界本地事件（开发功能）

next/local-diagnostics 实现 P07.4 的本地事件记录。events_enabled 默认 false，不改变单 percent 配置入口。

```json
{"percent":20,"events_enabled":true}
```

仅写本容器 state_dir/events.jsonl。每次启用立即尝试记录一次，此后持续启用期间每分钟最多尝试一次；显式关闭/开启会重新立即尝试。每份文件最多 64 条、64KiB，超出保留最新记录；稳定状态不定时追加心跳。一分钟内的变化合并为最新状态和 coalesced_changes 次数，不是完整审计日志，也不保证保留每个中间故障。

schema=crg-events-v1，记录 UTC 时间、Agent 状态、运行/资源模式、配置接受类别和逐项原因码计数。字段来自正向白名单；不记录任意 detail/error 原文、密码、配置内容、完整环境、业务路径/数据、容器 ID、设备身份或 journal 原值。未知原因码归为 unknown，不复制未知字符串。事件表示 Agent 控制结果，不能代替数据库健康与业务监控。

采用 0600 临时文件原子替换，不对可丢弃事件调用 fsync；原值 journal 保留全部同步持久化。现有文件符号链接、非普通文件、超限、坏 JSON 或未知 schema 时保留原文件并显示 status.events=unavailable，最多每分钟重试。资源协调继续；不会自动删除坏文件或重建恢复日志。修复事件路径后可在后续重试恢复。

关闭后保留最后文件。日志不会记录不同容器身份，持久状态目录跨重建时也可能保留旧记录，因此不能凭 events 文件判断当前身份/新鲜度；需结合 status 的当前身份及时间。当前诊断包仍按自己的白名单输出，不自动纳入该文件，不上传、不监听网络端口。

Windows 单元/vet 通过：默认关闭、每分钟合并、64 条/64KiB 上限、稳定状态不写、损坏保留、失败限频与恢复、脱敏以及失败不改变控制结果。Windows 不具备 POSIX 0600 语义，权限断言只在 Linux 执行。真实低 IO、长期异常和 Linux 故障实测继续归档；单元测试使用的模拟时间不能作为真实持续运行证据。
