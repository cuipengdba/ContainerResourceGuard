# 原镜像 Python2 启动与私有诊断 FIFO

内存百分比按用户决定使用 `memory.high`，不新增 `memory.max` 限制；现有 Kubernetes/运行时硬上限保留。达到 high 会触发回收/节流，但允许短时超过，不能承诺全局绝不 OOM。CPU、内存、IO 各自百分比、各默认20%，每容器一个 Agent、无权限不阻断原启动、v1跳过、每日文件/30天/1GB日志策略均保持。[preview.4](releases/v1.0.0-preview.4.md) 产品与附件未改变。

## 已完成的范围

[结构化结果](test-results-native-startup-private-fifo.json)与[完整证据](test-evidence/native-startup-private-fifo.json.gz)保存四份独立冻结计划、源码、完整报告和原始观察。最终855资格在原 DBS/HISDBS 镜像 Python2.7.5、postgres 用户下通过19项顶层检查；主机和两个镜像各保留原9个传输用例、19个启动参数校验用例，并新增13个 FIFO 用例（包含 Python2 解码参数产生的 unicode 路径）。

每个镜像另执行4次真实解释器启动：正常通道、无读取端、FIFO写满、未配置通道。测试只运行原 worker 的 `--help` 和一次自有 loopback HTTP 请求，不启动数据库业务或原600秒负载。8次启动都退出0；请求体 `{}`、四秒 socket 超时、完整响应保持，HTTP线程停止，标准输出仍为原 root 所有的 FIFO，读写标志不变。

正常场景收到1条带实际客户端端口的响应头注解；无读取端返回 ENXIO 并跳过激活，缺少通道配置跳过激活；写满场景激活成功但丢弃记录，原 HTTP/脚本继续。此处注解仍仅表示 `urlopen` 返回响应头，不替代原业务读取完整响应的成功判断。测试中的时钟只服务于自有请求，不能作为原 native 时钟或因果关联证据。

## 失败与修复边界

| 冻结任务 | 结果 | 记录检查/通过 | 事实 |
| --- | --- | ---: | --- |
| 843 | failed | 14/12 | 原版 site 阶段无 sys.argv，AttributeError；proc候选进一步遇到重新打开继承 stdout 的 errno13 |
| 848 | failed | 10/10 | 新 FIFO 的独立12用例通过，真实启动命令退出1；旧驱动未保留子命令stderr，未执行完19项 |
| 850 | failed | 19/17 | 候选与848完全相同，只改驱动保存stderr并继续两角色；两边均在注解数量检查失败，不能凭10或17项通过宣称成功 |
| 855 | passed | 19/19 | 接受 Python2 unicode 路径、加入第13例，并保存逐次启动状态；两个原镜像全部4场景通过 |

843在真实启动阶段观测到 sys.argv 尚未建立；proc解析只接受内核自身cmdline、固定脚本路径/数字run-id、原 worker SHA、三个隔离标记和同一 PID1 cgroup。旧 stdout 打开权限失败和其失败状态仍保留。新通道采用同用户0700目录及0600具名 FIFO，校验目录/文件类型、权限、所有者、链接数、打开前后 inode，使用 O_NOFOLLOW、O_NONBLOCK 和 CLOEXEC，不修改继承的 stdout。

845源码只接受 str，而 Python2 proc解码结果是 unicode，足以使合法路径被拒绝；这是静态解释，850报告只捕获到“注解数量断言失败”，没有捕获该内部 ValueError，不能伪称已直接记录它。855修复类型判断并实际通过该路径回归。每条注解最多512字节、最多1024条，不重试；读取端测试上界1MiB。原9用例的完整响应异常、原异常对象、载荷与超时等断言均保留。

## 清理与剩余工作

四个任务自然结束后，记录的4个任务父进程身份、7个原 Pod PID1 身份、7个叶cgroup和4个namespace由只读观察分别确认消失；只声明这些已记录身份，未推断未记录子进程。冻结文件SHA复核一致，未热改或重启原任务。848/850是为新候选和补齐错误捕获创建的新隔离单元，不是重跑原600秒业务求通过。

这些模块属于可选测试诊断器，尚未接入完整压力工厂的 FIFO 接收/清理链；接收端同样必须有边界、无读取端不得阻塞业务。BPF挂接就绪前的目标激活边界问题仍待修复。原831业务32项通过、诊断17/25失败、历史SQL/API超时、原52项定义、默认20%业务、正式24小时、memory.high七天604800秒/28周期及老化后置、其他架构/内核/设备/次版本迁移条件均不重评。稳定1.0尚未接受。
